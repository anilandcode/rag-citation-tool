The path

Five real steps. Not a prompt wrapper.

Every stage below is code in this repo, not a slide.

01

Ingest

PDF, DOCX, MD, TXT. Semantic split. Source, page, and section on every chunk.

02

Hybrid retrieve

Vector plus BM25, fused with reciprocal rank. Cohere rerank if a key is set.

03

Cite

The model must mark each fact as [Source: file, Page X].

04

Verify

A second pass asks if the cited chunk actually supports the sentence.

05

Refuse

If the documents do not say, the system says it does not know.

Retrieval

Two searches, then a fuse.

Vector search misses product codes, clause numbers, and policy IDs. BM25 catches the exact string. Reciprocal rank fusion merges both lists. That is why this is a retrieval system, not a chat skin.

Cohere cross-encoder is optional. Pinecone is optional persistence. The hosted demo runs in memory.

Evaluation

Scores you can rerun.

RAGAS and an audit report live in the same codebase as the query path. A team can see a baseline, change retrieval, and measure again. No invented company KPI on this page.

Differentiator

Citations are checked, not decorated.

The model is required to cite. Then a judge compares the claim sentence to the source chunk.

Questions

Straight answers about what is actually in the repo.

How is this different from LangChain?

LangChain is a kit. This is a finished citation path on LlamaIndex: hybrid retrieve, forced cites, claim verification, refusal, and an eval harness.

Is the hosted API always hot?

No. The Render box can cold-start. The demo may wait. Local uvicorn or Docker is the reliable path.

Does my data train a model?

No. Documents stay in the index you run. They are not used to train an external model.

Can you use our existing stack?

Yes. Most work is fixing the retrieval layer and adding verify, not a rewrite.
